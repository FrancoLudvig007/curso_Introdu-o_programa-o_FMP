Conceito 1

Da necessidade ao problema

Programar começa antes de abrir uma IDE: começa por entender qual problema precisa ser resolvido.

"Calcular as médias da turma."

PERGUNTAS QUE ESCLARECEM O PEDIDO

  • Quantos alunos serão avaliados?
  • Quantas notas cada aluno possui?
  • Como a média será calculada?
  • O que deve ser apresentado ao final?

PROBLEMA DESTA AULA

Uma turma tem 3 alunos. Cada aluno possui 3 notas.
Precisamos calcular e mostrar a média de cada um.

Um problema mal definido gera um programa que resolve a coisa errada — mesmo que o código esteja "correto".

Conceito 2

Pensar logicamente para resolver

Organizar ações de maneira coerente: o que acontece primeiro, que dados são necessários, como chegar ao resultado.

01

Entender

Identificar o que foi pedido.

02

Identificar dados

Descobrir quais informações serão necessárias.

03

Definir o resultado

Determinar o que deve ser produzido.

04

Planejar

Organizar as ações em ordem coerente.

05

Conferir

Verificar se o plano resolve o problema.

Essa sequência funciona para qualquer problema — da média de notas ao sistema mais complexo.

Conceito 3

Decomposição: dividir para conquistar

Um problema grande pode ser dividido em tarefas menores. Cada etapa é simples; juntas, resolvem o problema completo.

Problema grande → tarefas menores

  • Obter as três notas do aluno
  • Somar as notas
  • Dividir a soma por 3
  • Apresentar a média
  • Repetir para os demais alunos

Por que dividir ajuda?

  • Cada tarefa pequena é mais fácil de entender e testar
  • Erros ficam mais fáceis de localizar
  • A tarefa "calcular 1 média" só precisa ser pensada uma vez
  • É a base para, mais adiante, usar repetições no código

Conceito 4

Algoritmo: uma prévia

Um algoritmo é uma sequência finita de passos, organizados logicamente, com a finalidade de chegar a uma solução.

Exemplo: média de 3 notas

  1. Receber três notas
  2. Somar as notas
  3. Dividir a soma por três
  4. Mostrar a média

Todo algoritmo precisa ter:

  • Passos compreensíveis
  • Ordem coerente entre os passos
  • Um ponto de término

Veremos algoritmos com mais profundidade na próxima aula.

Uma decisão do curso

Por que não usar Portugol e VisualG?

Em muitos cursos, a lógica começa com pseudocódigo em Portugol — praticado na ferramenta VisualG.

O problema de usar Portugol primeiro

Com a carga horária curta, aprender uma linguagem didática e depois migrar para outra exigiria tempo adicional de adaptação.

Portugol e VisualG não são inúteis — são recursos didáticos válidos; apenas não serão a ferramenta deste curso.

Por que ir direto ao Python

  • Fundamentos praticados na linguagem real do curso
  • Python é usado em automação, análise de dados e desenvolvimento
  • Um só caminho de aprendizado, sem etapa de tradução extra
"A lógica não pertence a uma linguagem específica. O mesmo raciocínio pode ser representado em fluxograma, Portugol, Python, C ou outras."

Conexão com a Aula 01

O computador continua sendo literal

O computador não interpreta nossa intenção: executa instruções conforme foram definidas.

Suficiente para uma pessoa:

"Calcule a média."

Um programa precisa de instruções explícitas:

Quais valores? Qual operação? Quantas vezes? Como mostrar?

Conceito 5

Fluxogramas: os símbolos principais

Um fluxograma representa visualmente as etapas de um processo, por meio de símbolos conectados por setas.

SímboloNomeSignificadoUso
Oval / terminadorInício ou fimMarca os limites do processo
ParalelogramoEntrada ou saídaLer dados ou apresentar resultados
RetânguloProcessamentoCalcular ou atribuir valores
LosangoDecisãoAvaliar uma condição e escolher um caminho

A seta indica o fluxo: a sequência das etapas do início ao fim.
